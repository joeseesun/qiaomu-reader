# 4.9.1 书库可靠性验收

核对日期：2026-10-25。基线为已公开的 4.9.0。原开发目录有其他工作，修复在独立分支完成。

## 用户可见变化

- 默认按最近添加排序；可切换最近阅读、书名。中文书名使用拼音排序规则，导入时间有记录，既有图书退回文件创建时间。
- 下载位置固定为用户指定的下载目录，否则使用已配置书库目录，再否则为 `Books`。不再根据哪个文件夹书最多来猜位置。下载目录也纳入书架展示范围。
- 优先使用下载候选或本地容器元数据命名，缺元数据时清理文件名中的 Z-Library 标记，兼容 Windows 保留名。未改名既有书籍，避免破坏链接。
- SHA-256 精确查重：同内容提示已有并复用；不同内容同名书保留为独立文件。并发导入串行处理，避免同时导入两份相同文件。摘要按文件大小与修改时间失效，改名保留导入记录。
- 新封面缓存为最大 240×360 的独立 JPEG，不再把原图 base64 不断写进单个 JSON。旧缓存逐张迁移，原文件保留用于恢复。超过 120 本时书架只渲染可见范围与少量预加载行；继续阅读入口和键盘导航保留。
- 乔木 Home 按需回读独立封面文件，插件重启后不依赖旧的 base64 内存缓存；不读取书籍正文。
- MOBI/AZW3 的未标注类型封面根据图片头补 MIME 类型。

## 封面来源与边界

乔木书库后端目前通过 Z-Library Telegram bot 搜索和取得电子书。当前搜索解析只读取候选文字，返回书名、作者、格式等字段，没有把源站封面传给客户端；Open Library 作品匹配是补充封面来源。因此，仅放宽前端 URL 检查不会得到中文书封面。本次没有接入未经核实的源站封面 URL，也没有更改后端认证或下载链路。

本地书架优先使用书籍内嵌封面。本轮用原创 EPUB 经 Calibre 生成的 MOBI，在真实 Obsidian 提取到 1200×1800 的原内嵌 JPEG，再生成 240×360 缩略图。对照中未标注 MIME 的同一图片也能解码，所以 MIME 缺失不是已证实的用户原文件故障原因；仍需失败的原 MOBI 复现，不能宣称修复所有 MOBI。

## 验证

- 547 项 Node 测试；Python 语音与 Kindle 11 项、公开资产校验器 4 项；全量 ESLint、1,576 个语言键检查、标准/社区构建与安装包预算检查通过。
- Obsidian 1.14.5 / macOS 隔离库：3,000 个实际 TXT 书籍文件、长短标题混排。首部/25%/50%/95%/末尾分别验证；挂载 20–35 张卡片，最后一本索引 2999 可达，Home/End 焦点分别为 0/2999。260px、390px 和全宽容器无横向溢出。这是合成书库数据，不能代表 3,000 个复杂大体积 EPUB 的解析负载。
- 原创 EPUB 元数据命名、并发重复导入只落一份、不同内容同名版本保留两份均通过。
- 封面样本 47,463 字节 → 2,803 字节；旧 JSON 迁移后可用且原文件保留。
- 4.9.0 → 4.9.1 本地资产升级：自定义字号/主题/语言/目录/书架选择和阅读进度保留。测试库原插件与数据恢复，临时书库删除。
- 未做 Windows/移动设备真机回归；Windows 文件名和摘要行为有单元测试，不能替代真机证据。
