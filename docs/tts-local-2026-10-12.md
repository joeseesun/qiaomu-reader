# 本地语音：Kokoro 与 MeloTTS

状态：2026-10-12，4.7.0 候选。按用户决定，本地支持收敛为系统原生、Kokoro 和 MeloTTS；移除 F5-TTS、Spark-TTS、IndexTTS2 的安装器、模型适配、参考录音和导入音色入口。云端服务继续保留。旧本地模型选择迁移到 Kokoro 的默认音色，已下载的旧文件不自动删除。

## 播放器中的选择

播放器保持 Readwise 风格浮条，音色面板提供模型、音色、试听和「下载并使用」。就绪状态来自本机实际安装与合成校验，不能随 vault 同步。试听结束恢复原段落和倍速并暂停；试听本身不改变所选音色。

- **Kokoro FP32**：提供八个中文音色和三个英文音色，默认「知夏」，中文男声「言川」也标记推荐。阅读器显示名与原始 ID 分开保留，不声称这些名称是模型作者的命名。不使用此次 ARM 测试较慢且出现无效波形的 INT8 权重。
- **MeloTTS**：当前固定 Sherpa 模型只有一个中文音色，不伪造多个音色；支持词典覆盖范围内的英文词。任意英文、混合专名不能保证准确，详情中明确说明。
- **Mac 原生**：实际枚举 `AVSpeechSynthesisVoice.speechVoices()`，通过公共 AVSpeech API 合成。用户已试听认可的三个增强声音分别使用「清和」「知远」「书宁」显示名，原始 identifier 与选择保持不变，原始「声音 2 / 声音 4」可在来源中查看。不同 Mac 的实际可用声音可能不同。

本地模型按标点拆短句、最长 40 个 UTF-16 单位，保留原文偏移及 DOM Range；提前缓存至多三段。返回完整短句 WAV 后播放，并非传输实时 PCM 流。云端仍只提前请求一段，避免增加计费请求。关闭、跳段和切换服务取消旧任务，不跳过失败的文本。

模型来源：[Kokoro 权重](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)、[MeloTTS](https://github.com/myshell-ai/MeloTTS)。压缩包与每个解压文件的大小和 SHA-256 固定在清单；Melo 包的摘要是本次下载计算得到，并非发布者签名。固定 `uv 0.10.7`、Python 3.11.11、Sherpa-ONNX/Core 1.13.8、NumPy 2.4.6、SoundFile 0.13.1。不下载并执行模型仓库源码，不需要 PyTorch、MLX、CUDA、Xcode 或参考录音；传递依赖并非完整锁文件。

安装依次准备运行工具、托管 Python、按模型隔离环境、下载校验压缩包、严格解压、实际合成并验证有限且非静音的 PCM16 WAV，最后登记 ready。拒绝路径越界、符号链接、未列出文件、重复文件、大小和摘要不符。下载支持有限重试与 Range 续传；取消等待安装进程树退出后才释放锁。

## 存储与平台

```text
macOS: ~/Library/Application Support/qiaomu-reader/tts/
  uv / python/                  固定运行工具及托管 Python
  runtimes/<model>/<revision>/   模型私有环境
  models/<model>/<revision>/     权重、词典、发音资源
  worker-* / config-* / ready-* / endpoint-* / *.lock

macOS: ~/Library/Caches/qiaomu-reader/tts-cache/
  uv/                           依赖缓存
  audio/                        每次合成后清理的临时目录
  *.tar.bz2                     校验后的模型安装包
```

Windows 使用当前用户 LocalAppData，Linux 使用 XDG data/cache。存储根目录解析符号链接，拒绝放入已知 vault。插件只包含管理脚本与清单；模型、Python 和缓存不进入插件目录或 vault。卸载插件不自动删库外模型；本批没有模型卸载或磁盘迁移页面。

每个模型共用一个认证回环工作进程，只监听 `127.0.0.1` 临时端口，随机 Bearer 凭据保存在权限 0600 的本机文件；拒绝带 Origin 的请求。文本仅在请求体中，不拼 shell、不写长期日志。CPU 推理最多四线程，串行生成，空闲约 120 秒退出。取消客户端等待同时通知对应 job，生成 callback 在模型回调边界中止；不宣称可以瞬间打断一次底层计算。音频使用有界内存缓存，不持久保存书籍内容。

桌面启动工具覆盖 Mac/Windows/Linux x64 与 arm64；当前实际验证仅在 Apple M5 Pro、48 GiB、macOS 27.0.1 完成。其他平台还需真实安装和合成验证，不能将工具包存在等同于运行可用。

手机没有 Node/Electron，隐藏桌面安装入口；同步来的本地选择显示切换语音服务的恢复说明。手机仍可用已适配的云端服务、宿主实际提供的 Web Speech，或自行配置兼容 HTTPS 服务。未提供手机 Python、本地神经模型、电脑配对、隧道或锁屏播放保证。

## 验证记录

库外托管安装器已重新下载、校验并解压两个官方包，创建各自环境，实际合成校验登记 ready。相同 23 字中文测试句：Kokoro 女声 1.890 秒、男声 1.837 秒；MeloTTS 1.476 秒，均返回有效 WAV。首次冷加载与不同整机负载会增加等待。

此前独立基准与旧模型淘汰理由保存在 [性能报告](tts-speed-2026-10-12.md)。它是历史性能测量，不等同于全平台保证。最新候选通过 432 项 Node 回归、4 项 Python 回归、ESLint 零警告及 i18n；标准/社区包约 5.14 MB，低于 5.2 MB 预算。11 个 Kokoro 音色均实际生成有效 WAV。专用 Obsidian QA 实测两个模型播放、模型切换后的默认音色、旧设置迁移、保留云端配置、试听恢复原段落和倍速、四段连续播放与无 hover tooltip。

性能不能承诺瞬时启动或完全无停顿：第一轮 2 倍速冷播放在开头出现等待，现已增加高速播放前预备下一段。后续 1 倍速四段测得 Kokoro 首次等待 1.914 秒、第一处接句等待 307 ms；Melo 首次等待 3.295 秒、第一处等待 2.043 秒，其余接句 6–7 ms。随后的 2 倍速复用内存音频，7–8 ms 的接句结果只证明缓存播放，不证明冷合成跟得上。清缓存复测时 Obsidian CLI 返回未启用，未修改用户全局设置，因此最终高速冷合成与关闭续读需再次实机确认。第一轮宿主还报告 `isShown` 异常；第二次候选重载只有此前基线已有的 ResizeObserver 提示，异常来源尚未证实。

正式版仍未公开：先完成最终候选官方 Preview Scan 与发布门禁，默认分支保持已有可安装版本。
