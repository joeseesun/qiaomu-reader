# 连续朗读与自动翻页

4.7.0 候选。EPUB 在下一段离开可见页时定位其 CFI，等待定位结束再播放，读完当前章后继续下一可读章节。PDF 从当前源页面开始，逐页接续可提取文字，跳过空白文字页；不增加 OCR。

修复三处断点：

- PDF 原来只有当前页片段，没有后续页回调。
- DOM Range 的终点比较包含页末端点，下一段恰好从此处开始时被误判为仍在当前页；可见性改用不包含终点的范围。
- Foliate 的 view 丢掉了 renderer 的 relocation reason。自动跨章后，延迟重排的 `anchor` 事件可能被误认为用户查阅而停止跟随。适配器保留事件来源，自动重排不关闭跟随；手动离开朗读处仍暂停跟随，到章末等待用户继续。

控制器在定位期间响应暂停；此时继续不会提前播放。关闭、切书和跳段使旧异步任务失效，不允许迟到音频播放。选文仍只读选文，不修改整书朗读书签。

验证：控制器、UI 和 PDF 页接续测试覆盖定位等待、暂停/继续、关闭、页末边界、空白页、源页偏移和手动查阅。引擎集成测试覆盖上游丢弃 reason 后，适配器仍保留 navigation/anchor/page/scroll 来源。完整检查和标准/社区候选构建通过。

实机记录：macOS 27.0.1，隔离 Obsidian QA 库使用已安装的 MeloTTS。首轮自然播完《道德经》第十五章后进入第十六章（阅读位置 5/43 → 6/43），但随后误停跟随；据此补充上述事件来源修复。

修正后在合入文本格式的 4.7.0 安装包上复测：EPUB section 15 → 16 → 17 保持 playing/follow；Markdown、TXT、HTML 各三章测试文档均 0 → 1 → 2 自动接续且原文保持一致；三页文本 PDF 自动 1 → 2 → 3，最后 ended 且页面停在 3。使用真实本地模型输出、HTMLAudioElement 和播放器“从当前页”入口，确认音频 duration；为缩短验收时间，部分章节跳至末段并将正在播放的音频定位到结束前，让真实 ended 事件触发接续，不以伪造回调替代播放器。445 个 Node 测试、4 个 Python 测试、i18n 与源码 ESLint 通过。

另外实机确认：关闭播放器后状态 idle，重新打开回到同一朗读段落；手动跳到远处关闭跟随，到章末等待，点击继续后回到朗读位置并恢复自动跟随。两轮朗读脚本均未收集到运行错误。

首次升级时观察到宿主 ResizeObserver 通知；随后对 4.6.1 和 4.7.0 同库重载对照均未复现（各 0 条）。同名空白阅读笔记被验收脚本误选时，两版均报告 text-book-empty；脚本改为明确选择 .epub 后恢复正常。Windows、手机尚未真机验证。
